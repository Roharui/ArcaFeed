# 성능 최적화

`FeedCore`와 `ArcaFeed`·`RuliFeed` 공통으로 적용된 화면 초기화·게시글 이동·IndexedDB 저장소 최적화와 회귀 검증 방법을 정리합니다.

## 실행 경로

- 지원 페이지의 기본 레이아웃 CSS는 IndexedDB 초기 로드를 기다리기 전에 적용합니다. 설정과 Swiper 초기화는 저장소 준비 뒤에 실행합니다.
- 저장된 탐색 목록의 표준 pathname은 문자열 형식을 직접 검사하고 한 `Set`에서 중복 제거해 링크마다 불필요한 `URL` 객체와 임시 배열 생성을 피합니다.
- Swiper 생성 전에 읽기 이벤트와 건너뛰기 버튼만 연결하고, 목록 전체의 방문 표시·건너뛰기 알림·첫 이어보기 저장·탐색 버튼 생성은 `afterPaint()`로 첫 렌더링 이후로 미룹니다.
- 초기 HTML과 저장 목록을 먼저 사용하고 목록 보충 요청은 백그라운드에서 수행합니다.
- 구독 채널 요청은 `mapConcurrent`로 최대 4개씩 병렬 실행하고, 같은 URL과 타임아웃의 동시 GET은 `fetchUrl`에서 하나의 요청을 공유합니다.
- 지원하는 브라우저에서는 다음 글 문서 한 개를 `<link rel="prefetch" fetchpriority="low">`로 미리 불러옵니다.
- 프로덕션 빌드의 인라인 CSS는 `css-minify-loader.cjs`로 주석과 불필요한 공백을 압축합니다.
- 방문 기록은 실제 접근 시점까지 지연 로드하며 `load` 시점에도 이미 읽은 경우에만 갱신합니다.
- 저장소 주소 키(`addressId`)는 JSON 직렬화 없이 문자열로 결합하고, `equalData()`는 배열을 별도 키 배열 생성 없이 직접 비교합니다.
- 터치 시작(`touchStart`) 시점에 래퍼의 합성 레이어와 3D transform을 준비하고, 세로 스크롤로 판정되거나 전환이 끝나면 2D transform으로 복귀해 상시 합성 부담을 줄입니다.
- 댓글·하단 목록은 처음 측정한 높이를 확보한 뒤 `content-visibility: auto`로 화면 밖 렌더링을 미룹니다. `moveBefore()` 지원 브라우저에서는 슬라이드 이동 시 `iframe` 문서를 유지합니다.
- 드래그·전환 중 들어온 UI 갱신은 `updateAfterSwipe()`로 묶어 전환 뒤 화면을 그린 다음 실행하고, 가로 슬라이드는 컨테이너 너비가 바뀔 때만 프레임당 한 번 갱신합니다.

## IndexedDB 접근

- DB 버전 2는 `settings`·`channelFilters`·`navigationSessions`·`resumeSessions`·`progress`·`lists`·`meta`로 분리해 일반 객체를 직접 저장합니다.
- 시작 시 작은 레코드와 현재 탐색 목록만 읽고, 이어보기 목록과 체크포인트 대상 목록은 필요할 때만 비동기로 준비합니다.
- 위치 저장은 해당 세션과 위치만 읽고 `progress` 레코드 하나만 갱신하며, 트랜잭션 범위는 변경된 저장소와 검증에 필요한 저장소만 포함합니다.
- `BroadcastChannel` 알림은 `{ store, key }` 주소 배열만 전달하고 포커스 복귀 시에도 버전이 바뀐 사용 중 목록만 다시 읽습니다.
- 지원하지 않는 페이지는 DB를 열지 않으며, 구형 데이터 이전은 `versionchange` 트랜잭션에 격리합니다.

2026-11-17 로컬 Headless Chromium 157에서 `scripts/check-storage.mjs`로 목록에 100개씩 추가하는 15회 커밋과 전체 읽기의 중앙값을 비교한 결과입니다(청크 크기 500개).

| 초기 링크 | 저장 방식   | 추가 저장 | 전체 읽기 |
| --------: | ----------- | --------: | --------: |
|     2,000 | JSON 문자열 |     0.7ms |     0.6ms |
|     2,000 | 객체의 배열 |     0.8ms |     0.6ms |
|     2,000 | 500개 청크  |     0.4ms |     0.8ms |
|    20,000 | JSON 문자열 |     3.5ms |     2.7ms |

청크는 부분 저장에는 유리했지만 전체 읽기가 느려, 글 이동마다 전체 목록을 준비하는 현재 구조에서는 세션별 배열을 유지합니다.

## 반복 작업 최적화

- 표준 DOM API와 `hidden` 속성을 사용해 불필요한 스타일 계산을 줄입니다.
- 다음·이전 글 탐색 결과는 목록 참조·인덱스·건너뛰기 설정·방문 기록 revision이 같으면 캐시합니다.
- 최근 본 글 검색은 레코드별 정규화 문자열을 `WeakMap`에 캐시하고 검색어 토큰을 재사용합니다.
- 현재 글 위치는 저장된 인덱스를 먼저 확인하고 목록 참조별 `WeakMap<readonly string[], Map<string, number>>`에 캐시합니다.
- 지나온 링크가 200개를 넘으면 최근 100개만 남기고 인덱스를 보정합니다(구독 시리즈의 채널별 보충 커서는 유지).
- 좌우 드래그·전환 중에는 HTML 영상을 일시정지하고 복귀 시 기존에 재생 중이던 영상만 복원합니다.
- 이전 스냅샷과 비교해 바뀐 레코드만 저장하며, 설정·목록 정규화와 모달 탭 생성은 첫 접근까지 미룹니다.
- Webpack 파일시스템 캐시를 앱별 `.cache/webpack`에 분리해 사용합니다.

## 검증과 측정

```bash
npm run test:performance
npm --prefix ArcaFeed run bench:performance
npm --prefix RuliFeed run bench:performance
```

회귀 검증은 실제 TypeScript 모듈(`@feed/core` 포함)을 실행하고 LinkeDOM과 테스트 어댑터로 요청 중복, 실패, 병렬 한도, 초기화, 필터 변경 중 응답, 저장 횟수, 목록 중복, Swiper 재사용, UI 구독, 프레임별 리사이즈를 검증합니다.

2026-10-09 합성 벤치마크 비교 결과(URL 5,000개 동일 상태 1,000회 저장, 8개 채널 80ms 지연, 준비된 목록 초기화 80ms 지연):

| 합성 시나리오           |          수정 전 |  수정 후 |
| ----------------------- | ---------------: | -------: |
| 동일 상태 1,000회 저장  |         113.53ms |   0.16ms |
| 저장소 쓰기             |          7,000회 |      0회 |
| 직렬화 후 저장한 데이터 | 75,274,000바이트 |  0바이트 |
| 8개 채널 요청 완료      |         642.24ms | 160.70ms |
| 준비된 목록의 초기화    |          80.57ms |   0.17ms |

이는 합성 측정이며 실제 사이트 응답 시간·렌더링 FPS·브라우저 prefetch 효과를 의미하지 않습니다. 테스트와 벤치마크는 프로덕션 유저스크립트에 포함되지 않습니다.
