# 성능 최적화

화면 초기화와 게시글 이동의 대기 시간을 우선 줄였습니다. 사용자 설정과 런타임 의존성 버전은 유지했습니다.

## 실행 경로

- 초기 HTML과 저장 목록을 먼저 사용합니다. 목록 보충 요청은 백그라운드에서 수행하고, 응답이 도착하면 이동을 활성화합니다. 초기화의 이벤트 잠금이 네트워크 응답을 기다리지 않습니다.
- 구독 채널 요청은 최대 4개씩 병렬 실행합니다. 결과를 한 번 합쳐 정렬하며, 홈 시리즈 보충 중 이미 읽은 글과 현재 인덱스는 유지합니다.
- 같은 URL과 타임아웃의 동시 GET은 하나의 요청을 공유합니다. 완료 후에는 다시 요청할 수 있고 HTTP 실패도 호출자에게 전달됩니다.
- 지원하는 브라우저에서는 정확한 이동 URL로 다음 글 문서 한 개를 낮은 우선순위로 prefetch합니다. Swiper를 비활성화하면 prefetch도 제거됩니다. 브라우저와 서버 캐시 정책에 따라 이동 시 재사용 여부가 달라집니다.
- 스와이프 전환을 기본 300ms에서 120ms로 단축했습니다. 설정 적용 시 Swiper를 재사용하며, 빈 슬라이드 로더는 활성 슬라이드에서만 회전합니다.

## 반복 작업

- 저장은 이전 스냅샷과 비교해 바뀐 항목만 직렬화합니다. 동일 상태의 반복 저장은 저장소 쓰기를 하지 않고, 인덱스만 바뀌면 인덱스 한 항목만 저장합니다.
- 상태 갱신은 새 배열/객체를 사용합니다. 동일 값의 갱신은 구독 알림을 생략합니다. 저장 캐시 정리는 세션 변경 시 수행하며, 만료 세션은 저장소 한 번 순회로 삭제합니다.
- UI 구독은 한 번 설치합니다. 게시글 목록/인덱스 변경에는 UI 클래스와 너비를 다시 적용하지 않습니다.
- 리사이즈 이벤트를 `requestAnimationFrame`으로 묶어 프레임당 한 번만 너비를 계산·갱신합니다. 키보드 이벤트는 입력 요소마다 등록하지 않고 문서 한 곳에서 처리해 동적 모달 입력도 보호합니다.
- URL 중복 제거는 `Set`으로 수행합니다. 원격 목록에 세션 쿼리를 주입하지 않습니다. 제목은 행당 한 번만 읽고, 제목 차단만 설정한 경우와 하이브리드 목록도 필터링합니다.
- 목록 페이지는 최대 10개 탐색하며, 같은 페이지 URL을 다시 만나면 멈춥니다. 필터/세션 변경 전 요청의 결과는 버립니다.
- 개발/프로덕션 빌드에 Webpack 파일시스템 캐시를 사용합니다.

## 검증과 측정

```bash
npm run test:performance
npm run bench:performance
```

회귀 검증은 실제 TypeScript 모듈을 실행하고 네트워크·DOM·저장소 경계에 테스트 어댑터를 제공합니다. 추가 패키지 없이 요청 중복, 실패, 병렬 실행 한도, 초기화, 필터 변경 중 응답, 저장 횟수, 목록 중복, Swiper 재사용, UI 구독, 프레임별 리사이즈를 검증합니다.

벤치마크는 URL 5,000개를 가진 동일 상태를 1,000번 저장하고, 8개 채널에 요청당 80ms 지연을 줍니다. 현재 글과 다음 글이 준비된 초기화에도 80ms 목록 보충 지연을 줍니다. 초기 저장 비용과 TypeScript 변환 시간은 측정에서 제외합니다. 저장소는 메모리 어댑터이므로 실제 브라우저의 동기 저장 비용은 포함하지 않습니다.

2026-10-09의 동일 환경 비교 결과:

| 합성 시나리오           |          수정 전 |  수정 후 |
| ----------------------- | ---------------: | -------: |
| 동일 상태 1,000회 저장  |         113.53ms |   0.16ms |
| 저장소 쓰기             |          7,000회 |      0회 |
| 직렬화 후 저장한 데이터 | 75,274,000바이트 |  0바이트 |
| 8개 채널 요청 완료      |         642.24ms | 160.70ms |
| 준비된 목록의 초기화    |          80.57ms |   0.17ms |

이는 합성 측정이며 아카라이브의 실제 응답 시간, 렌더링 FPS 또는 브라우저 prefetch 효과를 측정한 수치가 아닙니다. 실행 시점과 시스템 부하에 따라 시간은 달라질 수 있습니다. 인앱 브라우저 연결을 사용할 수 없어 실제 사이트에서의 시각·터치 검증은 수행하지 못했습니다.

이전 코드가 있는 별도 디렉토리를 제공하면 같은 조건으로 다시 비교할 수 있습니다. 이전 디렉토리에는 `src/`가 필요합니다.

```bash
npm run bench:performance -- /path/to/before /path/to/after
```

새로 추가한 테스트와 벤치마크는 프로덕션 유저스크립트에 포함되지 않습니다.
