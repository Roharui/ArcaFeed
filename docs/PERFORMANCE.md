# 성능 최적화

화면 초기화와 게시글 이동의 대기 시간을 우선 줄였습니다. 사용자 설정과 런타임 의존성 버전은 유지했습니다.

## 실행 경로

- 지원 페이지의 기본 레이아웃 CSS는 IndexedDB 초기 로드를 기다리기 전에 적용합니다. 저장소 대기 후 사이드바·본문 너비가 뒤늦게 바뀌는 구간을 줄이며, 설정과 Swiper 초기화는 저장소 준비 뒤에 실행합니다.
- 저장된 탐색 목록의 표준 pathname은 문자열 형식을 직접 검사하고 한 Set에서 중복 제거합니다. 링크마다 URL 객체와 임시 배열을 만들지 않으며, 절대 주소·쿼리 등 다른 형식은 기존 URL 검증으로 처리합니다. 큰 목록도 첫 접근 시 전체 검증한다는 경계는 유지합니다.
- Swiper 생성 전에 읽기 이벤트와 건너뛰기 버튼만 연결합니다. 목록 전체의 방문 표시, 건너뛰기 알림, 첫 이어보기 저장과 탐색 버튼 생성은 animation frame 이후의 타이머로 미뤄 첫 화면을 그릴 기회를 줍니다. 초기화 명령 큐는 이를 기다리지 않으며, 프레임이 오지 않는 백그라운드 탭은 200ms 타이머로 처리합니다. 첫 저장 전에 페이지를 떠나거나 숨기면 체크포인트를 요청하고 예약된 첫 저장을 취소합니다. 기존 목록 준비가 필요한 경우 비동기 조회 뒤 저장하며, 페이지 종료만으로 완료를 보장하지는 않습니다. 방문 기록 기반 이동 판정과 이어보기 스크롤 복원은 초기화 중 유지합니다. 실제 기기의 대기 시간 개선량은 별도 측정이 필요합니다.
- 초기 HTML과 저장 목록을 먼저 사용합니다. 목록 보충 요청은 백그라운드에서 수행하고, 응답이 도착하면 이동을 활성화합니다. 초기화의 이벤트 잠금이 네트워크 응답을 기다리지 않습니다.
- 구독 채널 요청은 최대 4개씩 병렬 실행합니다. 결과를 한 번 합쳐 정렬하며, 홈 시리즈 보충 중 이미 읽은 글과 현재 인덱스는 유지합니다.
- 같은 URL과 타임아웃의 동시 GET은 하나의 요청을 공유합니다. 완료 후에는 다시 요청할 수 있고 HTTP 실패도 호출자에게 전달됩니다.
- 지원하는 브라우저에서는 정확한 이동 URL로 다음 글 문서 한 개를 낮은 우선순위로 prefetch합니다. Swiper를 비활성화하면 prefetch도 제거됩니다. 브라우저와 서버 캐시 정책에 따라 이동 시 재사용 여부가 달라집니다.
- 스와이프 전환 시간은 기존과 같은 300ms를 유지합니다. 설정 적용 시 Swiper를 재사용하며, 빈 슬라이드 로더는 활성 슬라이드에서만 회전합니다.
- 영상이 포함된 긴 게시글을 이동할 때 Swiper의 기본 3D transform 대신 2D transform을 사용하고 슬라이드의 강제 backface 합성을 끕니다. 영상 프레임마다 큰 게시글 레이어를 합성하는 부담을 줄이기 위한 변경이며, 실제 기기의 재생 FPS 개선량은 별도 확인이 필요합니다.
- 가로 슬라이드는 컨테이너 너비가 바뀔 때만 프레임당 한 번 갱신합니다. 첫 렌더링 이후 이미지가 로드되며 글 높이가 바뀌어도 전체 슬라이드를 재계산하거나 전환을 재설정하지 않습니다. ResizeObserver가 없는 환경에서는 기존 창 리사이즈 처리를 사용합니다.

## IndexedDB 접근

- DB 버전 2는 settings·channelFilters·navigationSessions·resumeSessions·progress·lists·meta로 분리하고 일반 객체를 저장합니다. 문자열 접두사 파싱, 데이터 JSON 변환·파싱 캐시, 필터 ID·최근 탐색 키의 중복 인덱스 배열과 공유 컬렉션 문자열 병합을 제거했습니다.
- 시작 시 작은 레코드와 현재 탐색 목록만 읽습니다. 이어보기는 선택한 목록만, 체크포인트는 비교와 한도 축소에 필요한 목록만 준비합니다. 동시 준비 호출도 실제 완료까지 같은 조회를 기다립니다.
- 목록과 메타데이터를 같은 스냅샷에서 준비하고, 이어보기 이동 직전에 최신 위치를 확인합니다. 이미 삭제된 항목으로 이동하지 않습니다.
- 위치 저장은 해당 세션과 위치를 읽고 progress 레코드 하나만 씁니다. 큰 목록·전체 요약 배열·전역 커밋 번호는 읽거나 쓰지 않습니다. 변경하지 않은 이름·필터·설정은 다시 저장하지 않습니다.
- 트랜잭션 범위는 관련 저장소만 포함합니다. 예를 들어 설정만 저장할 때 목록·읽기 위치·meta 저장소를 잠그지 않습니다. 겹치는 flush는 실행 Promise를 공유하고 다음 변경 배치도 순차 처리합니다.
- 알림은 저장소와 네이티브 키를 전달하며 필요한 레코드만 배치로 갱신합니다. 포커스 복귀는 작은 요약을 읽고 버전이 바뀐 사용 중 목록만 조회합니다. 미사용 목록과 전체 DB 키는 열거하지 않습니다.
- 보관 한도와 세션 삭제는 관련 레코드·목록·위치를 같은 트랜잭션에서 처리합니다. 다른 탭의 독립된 세션·이름·고정·위치는 보존하고 오래된 저장으로 삭제한 세션을 복원하지 않습니다.
- 지원하지 않는 페이지는 DB를 열지 않습니다. 구형 데이터 파싱과 정리는 DB 업그레이드에 격리하며 실패 시 원본을 유지합니다.
- 스크롤 체크포인트는 700ms debounce와 최대 5초 대기를 사용합니다.

### 초기 목록 검증 비용

2026-11-17 로컬 Headless Chromium 157에서 UI fixture의 실제 `VaultAdapter`를 사용해
상태 생성과 `articleList` 첫 접근을 측정했습니다. 별도 브라우저 context에 표준 pathname
목록과 현재 인덱스 0을 저장하고, 저장 완료 후 크기별 15회 실행한 중앙값입니다.
DB 초기 로드와 DOM·Swiper 렌더링은 이 구간에 포함하지 않습니다.

| 탐색 링크 | 수정 전 | 수정 후 |
| --------: | ------: | ------: |
|     2,000 |  10.4ms |   0.6ms |
|    20,000 |  95.4ms |   3.6ms |
|   100,000 | 481.1ms |  10.9ms |

저장된 표준 pathname의 직접 검증과 임시 배열 제거 효과이며, 실제 사이트·모바일의
전체 초기화 시간이나 화면 끊김 개선량을 의미하지 않습니다.

### 목록 청크화 비교

2026-11-17 로컬 Headless Chromium 157에서 `scripts/check-storage.mjs`를 실행했습니다. 같은 DB에서 목록에 100개씩 추가하는 15회 커밋과 전체 읽기의 중앙값이며 초기 적재는 제외했습니다. 청크 크기는 500개입니다.

| 초기 링크 | 저장 방식   | 추가 저장 | 전체 읽기 |
| --------: | ----------- | --------: | --------: |
|     2,000 | JSON 문자열 |     0.7ms |     0.6ms |
|     2,000 | 객체의 배열 |     0.8ms |     0.6ms |
|     2,000 | 500개 청크  |     0.4ms |     0.8ms |
|    20,000 | JSON 문자열 |     3.5ms |     2.7ms |
|    20,000 | 객체의 배열 |     3.5ms |     2.0ms |
|    20,000 | 500개 청크  |     0.5ms |     3.4ms |

청크는 긴 목록의 부분 저장에는 유리했지만 전체 읽기가 느렸습니다. 현재 유저스크립트는 글 이동마다 전체 탐색 목록을 다시 준비하고 목록 보충은 상대적으로 드물기 때문에 세션별 배열을 유지합니다. 범위 단위로 탐색·렌더링하는 런타임으로 바꾸는 경우 다시 검토합니다. 객체 저장만으로 모든 경우가 빨라지는 것은 아니며 레코드 분리·불필요한 변환 제거와 작은 갱신 단위가 주된 개선입니다. 위 수치는 단일 데스크톱 브라우저의 합성 조건이며 실제 사이트나 모바일 성능을 의미하지 않습니다.

## 반복 작업

- 스크롤 체크포인트는 목록·탐색 조건이 같으면 링크 복사·비교를 생략하고 위치만 저장합니다. 저장소의 탐색 정보가 다른 탭에서 변경·삭제됐으면 이 경로를 거부하고 기존 체크포인트 처리로 돌아갑니다. 위치 저장은 다른 탭의 최신 위치를 병합합니다.
- 여러 채널 목록을 조회할 때 기존 링크 Set은 읽기 전용으로 공유하고, 채널별 Set에는 새로 발견한 링크만 보관합니다. 채널마다 전체 기존 목록을 복사하지 않으며 기존 링크·페이지 간 중복 제거는 유지합니다.

- 다음·이전 글 탐색 결과는 목록 참조, 현재 인덱스·글, 건너뛰기 설정과 방문 기록 revision이 같으면 재사용합니다. 빈 결과도 캐시하며, 방문 기록이나 탐색 상태가 바뀌면 다시 검색합니다. 건너뛴 글 개수는 중간 배열을 만들지 않고 계산합니다.
- 최근 본 글 검색은 레코드별 정규화 문자열을 WeakMap에 저장하고 검색어 토큰을 재사용합니다. 같은 검색 조건의 더 보기에서는 필터 결과를 재사용하며, 기록이 바뀌면 갱신합니다. 이어보기의 방문 글·채널 해시맵은 방문 기록 참조가 바뀔 때만 재구성하고 검색 문자열 캐시도 함께 무효화합니다. 부분 문자열·다중 단어·NFKC 정규화 검색 동작은 유지합니다.
- 이어보기 위치 병합과 구독 채널 숨김 검사의 중첩 배열 검색은 Set 조회로 처리합니다. 이어보기 복원은 현재 글 인덱스를 한 번만 찾고, 보관 범위 생성은 이미 찾은 인덱스로 현재 글 포함 여부를 판단합니다.

- 현재 글 위치는 저장된 인덱스의 링크를 먼저 확인합니다. 불일치할 때만 배열을 검색하고, 경로별 결과는 목록 참조를 키로 하는 WeakMap 안의 Map에 캐시합니다. 전체 해시맵을 페이지마다 생성하거나 직렬화하지 않으며, 목록 교체 시 이전 캐시도 GC 대상이 됩니다.
- 지나온 링크가 200개를 넘으면 최근 100개만 남기고 저장 인덱스를 보정합니다. 아직 이동하지 않은 링크는 모두 유지하며 구독 시리즈는 채널별 보충 조회에 필요한 가장 오래된 링크도 보존합니다. 기존 저장 목록에도 적용하지만, 아직 읽지 않은 대규모 스크랩·셔플 목록의 로드 비용 자체를 없애지는 않습니다.
- 목록 보충 여부는 이동 가능한 다음 글 3개를 찾으면 즉시 판단합니다. 전체 나머지 목록을 복사·필터링하지 않습니다.

- 실제 좌우 드래그와 슬라이드 전환 중에는 HTML 영상을 일시정지하고 재생 이벤트도 차단합니다. 현재 글로 복귀하면 기존에 재생 중이던 영상만 복원합니다. 영상 프레임을 주기적으로 검사하지 않고 Swiper와 미디어 이벤트로 처리합니다.

- 저장은 이전 스냅샷과 비교해 바뀐 레코드만 저장합니다. 동일 상태의 반복 저장은 저장소 쓰기를 하지 않고, 인덱스만 바뀌면 인덱스 한 항목만 저장합니다.
- 상태 갱신은 새 배열/객체를 사용합니다. 동일 값의 갱신은 구독 알림을 생략합니다. 저장 캐시 정리는 세션 변경 시 수행하며, 만료 세션은 작은 메타데이터에서 골라 관련 레코드를 삭제합니다.
- UI 구독은 한 번 설치합니다. 게시글 목록/인덱스 변경에는 UI 클래스와 너비를 다시 적용하지 않습니다.
- 방문 기록, 이어보기 목록, 스크롤 위치 알림을 분리합니다. 스크롤 저장은 전체 상태 알림이나 본 글 표시·기록 모달 재렌더링을 유발하지 않습니다. UI 설정도 실제로 바뀐 클래스나 너비만 적용합니다.
- 이어보기 요약·목록·위치를 각각 resumeSessions·lists·progress의 세션별 레코드에 저장합니다. 존재 확인과 모달은 요약만 사용하며 위치 변경이 큰 목록을 다시 쓰지 않습니다.
- 이어보기는 최대 20개 세션, 세션당 최대 2,000개·전체 최대 5,000개 링크로 제한합니다. 최근 세션부터 목록을 배분하며 모든 세션의 현재 글을 유지합니다. 기존 대용량 데이터는 DB 업그레이드에서 정리하며, 한시적 이전 코드는 별도 모듈에 격리합니다. 일반 탐색 캐시는 최근 5개를 유지하며, 목록에 누락된 오래된 캐시도 정리합니다.
- 설정을 로드한 스냅샷을 저장 비교의 기준으로 사용하고, 저장소에서도 같은 객체 값의 쓰기를 생략합니다. 페이지를 다시 열거나 방문 기록만 갱신할 때 설정·목록을 다시 저장하지 않습니다.
- 리사이즈 이벤트를 `requestAnimationFrame`으로 묶어 프레임당 한 번만 너비를 계산·갱신합니다. 키보드 이벤트는 입력 요소마다 등록하지 않고 문서 한 곳에서 처리해 동적 모달 입력도 보호합니다.
- URL 중복 제거는 `Set`으로 수행합니다. 원격 목록에 세션 쿼리를 주입하지 않습니다. 제목은 행당 한 번만 읽고, 제목 차단만 설정한 경우와 하이브리드 목록도 필터링합니다.
- 목록 페이지는 최대 10개 탐색하며, 같은 페이지 URL을 다시 만나면 멈춥니다. 필터/세션 변경 전 요청의 결과는 버립니다.
- 개발/프로덕션 빌드에 Webpack 파일시스템 캐시를 사용합니다.

- 설정·목록의 정규화는 getter 첫 접근까지 미루며 상태 복사도 지연 상태를 유지합니다. 채널 필터와 설정 그룹은 별도 레코드이며 모달 탭·화면 너비 변경이 다른 그룹의 getter를 실행하지 않습니다. 일반 경로에서 JSON 문자열 파싱은 사이트 방문 기록에만 필요합니다.
- 설정 모달은 선택한 탭만 생성하고 나머지 탭은 처음 선택할 때 생성합니다. 최근 본 글·이어보기 탭을 사용하지 않으면 조회·렌더링·구독을 시작하지 않습니다. 방문 기록이 꺼져 있으면 원본 방문 JSON 문자열도 읽지 않습니다.

## 검증과 측정

```bash
npm run test:performance
npm run bench:performance
```

회귀 검증은 실제 TypeScript 모듈을 실행하고 네트워크·DOM·저장소 경계에 테스트 어댑터를 제공합니다. 추가 패키지 없이 요청 중복, 실패, 병렬 실행 한도, 초기화, 필터 변경 중 응답, 저장 횟수, 목록 중복, Swiper 재사용, UI 구독, 프레임별 리사이즈를 검증합니다.

벤치마크는 URL 5,000개를 가진 동일 상태를 1,000번 저장하고, 8개 채널에 요청당 80ms 지연을 줍니다. 현재 글과 다음 글이 준비된 초기화에도 80ms 목록 보충 지연을 줍니다. 초기 저장 비용과 TypeScript 변환 시간은 측정에서 제외합니다. 저장소는 메모리 어댑터이므로 실제 브라우저의 동기 저장 비용은 포함하지 않습니다.

2026-10-09의 동일 환경 비교 결과:

| 합성 시나리오           |          수정 전 |  수정 후 |
| ----------------------- | ---------------: | -------: |
| 동일 상태 1,000회 저장  |         113.53ms |   0.16ms |
| 저장소 쓰기             |          7,000회 |      0회 |
| 직렬화 후 저장한 데이터 | 75,274,000바이트 |  0바이트 |
| 8개 채널 요청 완료      |         642.24ms | 160.70ms |

이는 합성 측정이며 아카라이브의 실제 응답 시간, 렌더링 FPS 또는 브라우저 prefetch 효과를 측정한 수치가 아닙니다. 실행 시점과 시스템 부하에 따라 시간은 달라질 수 있습니다. 인앱 브라우저 연결을 사용할 수 없어 실제 사이트에서의 시각·터치 검증은 수행하지 못했습니다.

이전 코드가 있는 별도 디렉토리를 제공하면 같은 조건으로 다시 비교할 수 있습니다. 이전 디렉토리에는 `src/`가 필요합니다.

```bash
npm run bench:performance -- /path/to/before /path/to/after
```

새로 추가한 테스트와 벤치마크는 프로덕션 유저스크립트에 포함되지 않습니다.
