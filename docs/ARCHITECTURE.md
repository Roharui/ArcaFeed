# 아키텍처와 실행 보장

ArcaFeed는 페이지마다 실행되는 유저스크립트입니다. `core/index.ts`는 상태 저장소와 이벤트 실행기를 조립하고, 기능 모듈은 `core/app-events.ts`의 타입이 지정된 이벤트 버스에 명령을 발행합니다.

## 의존성 방향

```text
진입점 → 애플리케이션 조립 → 이벤트 실행기 → 기능 모듈
                            기능 모듈 → app-events → EventBus
                            기능 모듈 → VaultAdapter → Store / ConfigService
                                                       ConfigService → 저장소 / 스키마 검증
```

기능 모듈에서 조립 모듈인 `@/core`를 가져오면 `core → feature → core` 순환 참조가 생깁니다. 이벤트 전송에는 `@/core/app-events`를 사용합니다. 같은 디렉토리의 모듈도 자신을 다시 내보내는 barrel 대신 구체적인 모듈을 가져옵니다. 회귀 테스트는 타입 전용 import를 제거한 실제 런타임 의존성 그래프에 순환이 없는지 검사합니다.

## 이벤트와 실패 처리

이전에는 명령 실행 중 발생한 모든 이벤트를 `isRunning` 검사로 버렸습니다. 초기화 중 설정 클릭이나 실행 중 발생한 슬라이드 완료 이벤트가 사라질 수 있었습니다.

`EventQueue`는 서로 다른 명령을 도착 순서대로 처리합니다. 같은 이벤트가 아직 대기 또는 실행 중이면 기존 실행을 공유합니다. 따라서 모달 확인을 연속 클릭해도 모달을 닫은 뒤 빈 입력을 다시 읽지 않습니다. 이벤트를 발행한 호출자는 실행 완료까지 기다릴 수 있고, 실패한 명령 이후에도 큐는 계속 처리됩니다. 실행 중인 명령 내부에서 후속 이벤트를 발행할 때는 기다리지 않고 발행해야 합니다. 같은 큐에 들어간 후속 명령은 현재 명령이 끝나야 실행됩니다.

`StepRunner`는 단계 사이의 순서를 유지하며 한 단계의 배열 안에 있는 함수들을 병렬 실행합니다. 하나라도 실패하면 이미 실행 중인 함수들이 모두 끝날 때까지 기다린 뒤 오류를 전달하고 후속 함수와 다음 단계를 건너뜁니다. 동기 오류, 비동기 오류, 개발 빌드, 프로덕션 빌드에 같은 정책을 적용합니다. `mapConcurrent`도 실패 후 추가 요청을 시작하지 않고 실행 중인 요청의 완료를 기다립니다.

EventBus는 모든 구독자의 완료를 기다리고 `CommandResult`를 반환합니다. 모두 성공하면 `{ ok: true }`, 예외·명시적 실패·미등록 명령이면 `{ ok: false, errors }`를 반환하며 다른 구독자는 계속 호출합니다. 애플리케이션 조립 모듈은 실행기 실패를 결과로 전달하며, `StepRunner`도 명시적 실패 뒤의 단계를 실행하지 않습니다. 별도로 시작한 배경 조회나 목적지 문서 로드의 성공까지 보장하지는 않습니다. `OperationError`는 오류 종류와 원인을 보존하고 같은 오류의 사용자 안내를 한 번만 표시합니다. 이미 수행한 DOM 작업 전체를 되돌리는 트랜잭션은 제공하지 않습니다.

## 상태와 비동기 요청

시리즈 생성이나 필터 변경처럼 여러 필드가 함께 바뀌는 경우에는 `VaultAdapter.updateState()`로 한 번에 반영합니다. 구독자는 새 키와 이전 목록이 섞인 중간 상태를 보지 않습니다. `resetArticleList()`는 목록과 활성 인덱스를 함께 초기화하고 조회 revision을 증가시킵니다. 어댑터를 파괴할 때도 revision을 증가시킵니다.

`captureArticleSession()`은 조회 시작 시 revision, 세션 키, 페이지 정보, 필터 참조, 검색 조건, 시리즈/셔플 모드, 홈 시리즈 채널 목록을 캡처합니다. 응답을 반영하거나 다음 목록 페이지를 요청하기 전에 캡처가 현재 상태와 같은지 확인합니다. 첫 배치, 스크랩 전체 배치, 홈 시리즈 생성/보충과 백그라운드 인덱스 갱신에 같은 기준을 적용합니다. 무효화된 응답은 목록·인덱스·페이지 이동·실패 토스트에 반영하지 않습니다. 이미 전송한 HTTP 요청 자체를 취소하지는 않으며 기존 타임아웃이 적용됩니다.

목록을 덧붙일 때는 응답이 도착한 시점의 최신 목록과 중복 제거합니다. 홈 시리즈 보충은 읽은 구간과 현재 인덱스를 유지합니다. 새 홈 시리즈는 결과가 있을 때만 완성된 상태로 전환합니다.

구독 채널 조회는 실패를 채널별 결과로 수집해 성공한 채널의 피드를 시작합니다. 자동 보충은 실패 채널을 제외하고, 개별 재시도는 최신 목록의 현재 글까지 보존한 뒤 뒤쪽에 결과를 병합합니다. 목록과 실패 상태는 한 번에 반영하며, 보충·재시도는 페이지당 하나만 실행합니다. 조회가 무효화되면 후속 페이지를 요청하거나 응답을 반영하지 않습니다. 구독 설정은 조회 전에 저장하며, 조회 실패·빈 결과에도 적용한 설정을 유지합니다.

페이지 이동은 유효한 배열 인덱스에 대해서만 수행합니다. `feature/navigation.ts`는 현재 페이지 저장과 대상 세션 준비가 성공한 뒤 이동합니다. 저장·이동 예외 시 변경한 탐색 상태·인덱스·Swiper 위치·체크포인트 중지·임시 스크롤 전달을 복구하고 재시도를 허용합니다. 구독의 이미 적용한 채널·필터 설정은 유지합니다. 복구 저장도 실패하면 현재 페이지를 유지하고 실패를 안내합니다. 같은 페이지에서 이동이 시작된 뒤 들어온 추가 이동 이벤트는 처리하지 않으며, BFCache 복귀 시 가드를 해제합니다. 시리즈 새 탭은 팝업 차단을 확인하고 opener를 끊은 뒤 준비한 세션으로 이동하며, 실패하면 빈 탭을 닫습니다.

## 저장소 경계

ArcaFeed 소유 영속 데이터는 IndexedDB `ArcaFeed` 버전 2에 일반 객체로 저장합니다. 문자열 `Storage` API와 JSON 캐시를 사용하지 않습니다. `record-schema.ts`는 저장소 이름·레코드 주소·변경분 형식을, `StorageRepository`는 설정·탐색·이어보기 도메인 API를 제공합니다. 앱의 동기 `Store`와 지연 getter는 유지하며 저장소 경계에서 필요한 데이터만 준비합니다. 앱 상태의 Proxy·getter·Swiper 객체를 직접 저장하지 않고 필드가 명시된 객체·배열을 만듭니다.

| Object store         | 기본 키      | 내용                                                          |
| -------------------- | ------------ | ------------------------------------------------------------- |
| `settings`           | `id`         | display·subscription·reading·lastModalTab·shuffle·versionInfo |
| `channelFilters`     | 채널 ID      | 채널별 필터 객체                                              |
| `navigationSessions` | articleKey   | mode·query·channels·실패 상태·목록 버전·최근 사용 시각        |
| `resumeSessions`     | 이어보기 ID  | 이름·고정·탐색 문맥·현재 글·목록 개수·목록 버전               |
| `progress`           | `[kind, id]` | navigation의 인덱스 또는 resume의 스크롤·갱신 시각            |
| `lists`              | `[kind, id]` | 순서가 있는 pathname 배열과 목록 버전                         |
| `meta`               | `id`         | 스키마 이전 상태                                              |

`kind`는 navigation 또는 resume입니다. 채널 필터 ID와 최근 탐색 키의 별도 인덱스 배열은 저장하지 않습니다. 필터는 실제 레코드에서 열거하고, 탐색 캐시는 최근 사용 시각으로 5개를 유지합니다. 내부 mode는 channel·series·scrap·subscription이며 런타임의 기존 플래그는 어댑터에서 해석합니다. 검색 조건에는 articleKey를 저장하지 않고 URL을 만들 때 추가합니다. 이어보기의 `context` unique index는 정렬한 전체 검색 조건과 채널 또는 원래 시리즈 키를 배열로 보관합니다. 새 채널 문맥 ID는 전체 조건에서 결정하므로 32비트 해시 충돌로 세션을 합치지 않으며 이전 ID도 문맥 조회로 재사용합니다.

시작 시 지원하지 않는 페이지를 DB 접근 전에 제외합니다. 지원 페이지는 작은 설정·메타데이터·위치 레코드와 현재 articleKey의 탐색 목록만 읽고 앱을 생성합니다. 이어보기는 `prepareList(id)`, 체크포인트는 `prepareSession(session)`이 Promise를 반환하면 완료를 기다린 뒤 동기 목록 getter나 `saveSession()`을 사용합니다. 준비는 비교할 기존 세션과 링크 한도로 축소할 목록만 로드합니다. 요청 중인 목록도 준비 완료로 오인하지 않으며, 목록과 그 메타데이터를 같은 스냅샷에서 읽습니다. 이어보기 이동은 준비 후 최신 요약·위치를 다시 확인하고 삭제된 항목에서는 중단합니다.

쓰기·삭제는 먼저 메모리 캐시에 반영하고 microtask에서 모아 커밋합니다. 같은 레코드의 필드 변경만 최신 DB 값에 적용하며 관련 읽기와 쓰기는 같은 readwrite 트랜잭션 안에서 수행합니다. 자동 체크포인트는 다른 탭이 바꾼 이름·고정을 덮어쓰지 않습니다. 기존 세션이 삭제됐으면 오래된 체크포인트로 복원하지 않습니다. 위치는 현재 세션과 path를 검사하고 최신 updatedAt을 우선합니다. 새로 고정한 항목은 오래된 캐시의 자동 정리로 삭제하지 않습니다. 명시적인 삭제는 목록·위치도 같은 트랜잭션에서 정리합니다.

트랜잭션의 범위는 변경한 object store와 그 검증에 필요한 저장소만 포함합니다. 스크롤 위치 저장은 해당 위치와 세션을 조회하고 작은 위치 레코드 하나만 갱신합니다. 설정만 저장할 때는 위치·목록·meta 저장소를 잠그지 않습니다. 모든 쓰기가 공통 전역 커밋 번호를 갱신하는 구조도 제거했습니다. 레코드는 revision을, 목록과 부모 요약은 별도의 listVersion을 공유합니다.

`flushSave()`는 앱 변경을 저장 큐에 반영하고 `flushStorage()`는 실제 커밋 완료를 기다립니다. 겹치는 flush는 하나의 실행 Promise를 공유하고 실행 중 추가된 변경도 순차 커밋합니다. 실패한 변경은 큐에 남겨 다음 저장에서 최신 DB 값에 다시 적용합니다. 공용 `navigate()`와 명령 실행 완료는 커밋을 기다리며 실패 시 이동을 중단합니다. 복구 저장은 이전 탐색 상태를 재기록합니다. DOM 변경 전체를 되돌리는 트랜잭션은 제공하지 않습니다.

`BroadcastChannel`은 `{store, key}` 주소 배열을 알립니다. 수신 탭은 알림을 모아 변경한 작은 레코드와 이미 사용 중인 목록만 조회합니다. 캐시 전체 반영 후 `arcafeed:storage`의 `detail.changes`로 한 번 알립니다. 아직 커밋하지 않은 로컬 변경은 덮어쓰지 않습니다. 포커스·pageshow에서는 작은 레코드를 다시 읽고 listVersion이 바뀐 사용 중 목록만 복구합니다. 전체 키 목록이나 아직 사용하지 않는 목록 값은 열거하지 않습니다.

`ReadingHistory`는 사이트 방문 기록(entries), 이어보기 탐색 정보(sessions), 위치(progress)를 독립적으로 알립니다. 스크롤 저장은 방문 표시·건너뛰기 revision이나 기록 모달 전체 렌더링을 유발하지 않습니다. 존재 확인과 이어보기 모달은 요약만 사용하며 목록 getter는 선택한 목록만 정규화합니다. 최대 20개 세션, 세션별 2,000개·전체 5,000개 링크 한도를 트랜잭션 안에서도 적용합니다. 고정 항목을 우선하고 정리하는 목록에도 각 세션의 현재 글을 보존합니다. 20개가 모두 고정된 것을 이미 알고 있으면 새 세션 저장은 false를 반환하며, 다른 탭에서 뒤늦게 한도가 찬 경우 커밋 결과를 캐시에 반영합니다.

사이트가 소유한 `recent_articles`·`recent_disabled`는 localStorage에서 읽기만 합니다. 방문 판정은 전체 유효 기록, 최근 본 글 표시는 최신 300개를 사용합니다. 방문 기록이 비활성화되면 큰 원본 기록은 읽지 않습니다. 탭 전용 스크롤·토스트 전달은 sessionStorage를 사용합니다. 스크롤 체크포인트는 700ms debounce와 최대 5초 대기를 사용하며 페이지 종료만으로 비동기 준비·저장 완료를 보장하지 않습니다.

저장 객체도 신뢰할 수 있는 입력으로 간주하지 않습니다. `config-schema.ts`와 `reading-session-schema.ts`가 필드·pathname·인덱스와 기본값을 검증합니다. 상태 배열과 객체는 새 참조로 갱신하고 캐시된 값을 직접 수정하지 않습니다. 설정의 용도별 정규화와 모달 탭 생성도 첫 접근까지 미루며 상태 복사는 미사용 getter를 실행하지 않습니다.

## 필터와 접근성

채널 필터의 선택적 `includeTitle`·`includeMode`·`includeCaseSensitive`는 저장 경계에서 검증합니다. 기존 필터는 포함 조건 없이 동작하고 빈 포함 조건은 저장하지 않습니다. 공용 필터 판정은 제목 차단을 우선하며, 일반·하이브리드·구독 목록에 같은 any/all·대소문자 조건을 적용합니다.

`modal/focus.ts`는 최상단 대화상자의 초기 포커스·Tab 순환·외부 포커스 유입·Escape·닫기 후 복원을 담당하고 종료 시 리스너를 해제합니다. 내부 이름 편집과 IME Escape를 존중합니다. 글 이동 단축키는 편집 가능한 composed path·IME·키 반복·수정키·열린 모달에서 실행하지 않습니다. `swiper/motion.ts`는 동작 줄이기 설정에 따라 전환 속도를 갱신하고 파괴 시 리스너를 해제합니다.

`swiper/side-click.ts`는 화면 폭 1024px 이상에서 현재 본문의 좌우 빈 공간 클릭을 기존 이전·다음 스와이프 명령으로 전달합니다. 클릭 시 본문 경계를 측정하므로 화면·본문 너비 변경을 반영합니다. 본문·별도 컨트롤·드래그·선택 영역·수정키·열린 대화상자·비활성 스와이프·전환 및 이동 중 상태를 제외하고, 해당 방향의 이동 가능 상태를 따릅니다. Swiper 파괴 시 문서 리스너를 해제합니다.

## 구형 데이터 이전

`record-migration.ts`는 DB versionchange 트랜잭션에서만 실행합니다. v1 values 문자열과 아직 이전하지 않은 ArcaFeed localStorage 키를 읽어 검증·분리하고 새 레코드와 meta.schema를 기록합니다. v1 이전 완료 마커가 있으면 IndexedDB 값을 우선하고 오래된 localStorage 값은 다시 가져오지 않습니다. 구형 통합 설정과 이어보기 목록도 이 경계에서 함께 변환합니다. 동일 문맥은 정리하고 이름·고정·위치·순서와 보관 한도를 보존합니다.

새 레코드 쓰기와 구형 values 저장소 삭제는 같은 업그레이드 트랜잭션에 속합니다. 실패하면 DB 버전과 원본이 복구되며 localStorage도 남깁니다. 성공한 뒤에만 ArcaFeed 소유 localStorage 키를 삭제합니다. versionchange를 받은 기존 연결은 닫고 이후 저장을 중단하여 새로고침을 요구합니다. 다른 탭 때문에 업그레이드가 blocked면 원인을 안내합니다. 구형 형식 지원 종료 시 record-migration.ts와 reading-history-migration.ts를 정리하되 DB 스키마 생성과 실패 복구 검증은 유지합니다. 일반 조회·저장 경로에는 JSON 형식 호환 분기를 두지 않습니다.

## 탐색 기능 구분

`vault/navigation-context.ts`의 `navigationMode()`는 채널(`channel`), 일반 시리즈(`series`),
스크랩(`scrap`), 구독 피드(`subscription`)를 구분합니다. 스킵 허용 여부, 읽기 설정 키와
표시 이름, 설정 탭 및 시리즈 열기 버튼은 이 공통 판별을 사용합니다.
구독 피드에서는 최근 본 글 스킵을 사용할 수 있고 일반 시리즈와 스크랩에서는 제한합니다.
기존 저장된 세션과 이어보기 호환을 위해 `isSeriesMode`, `isScrapMode`, `seriesChannels`는
유지하며, 공통 판별 함수가 이 저장 형식을 기능별 모드로 해석합니다.
