# 아키텍처와 실행 보장

ArcaFeed는 페이지마다 실행되는 유저스크립트입니다. `core/index.ts`는 상태 저장소와 이벤트 실행기를 조립하고, 기능 모듈은 `core/app-events.ts`의 타입이 지정된 이벤트 버스에 명령을 발행합니다.

## 의존성 방향

```text
진입점 → 애플리케이션 조립 → 이벤트 실행기 → 기능 모듈
                            기능 모듈 → app-events → EventBus
                            기능 모듈 → VaultAdapter → Store / ConfigService
                                                       ConfigService → 저장소 / 스키마 검증
```

기능 모듈에서 조립 모듈인 `@/core`를 가져오면 `core → feature → core` 순환 참조가 생깁니다. 이벤트 전송에는 `@/core/app-events`를 사용합니다. 같은 디렉토리의 모듈도 자신을 다시 내보내는 barrel 대신 구체적인 모듈을 가져옵니다. 회귀 테스트는 타입 전용 import를 제거한 실제 런타임 의존성 그래프에 순환이 없는지 검사합니다.

## 이벤트와 실패 처리

이전에는 명령 실행 중 발생한 모든 이벤트를 `isRunning` 검사로 버렸습니다. 초기화 중 설정 클릭이나 실행 중 발생한 슬라이드 완료 이벤트가 사라질 수 있었습니다.

`EventQueue`는 서로 다른 명령을 도착 순서대로 처리합니다. 같은 이벤트가 아직 대기 또는 실행 중이면 기존 실행을 공유합니다. 따라서 모달 확인을 연속 클릭해도 모달을 닫은 뒤 빈 입력을 다시 읽지 않습니다. 이벤트를 발행한 호출자는 실행 완료까지 기다릴 수 있고, 실패한 명령 이후에도 큐는 계속 처리됩니다. 실행 중인 명령 내부에서 후속 이벤트를 발행할 때는 기다리지 않고 발행해야 합니다. 같은 큐에 들어간 후속 명령은 현재 명령이 끝나야 실행됩니다.

`StepRunner`는 단계 사이의 순서를 유지하며 한 단계의 배열 안에 있는 함수들을 병렬 실행합니다. 하나라도 실패하면 이미 실행 중인 함수들이 모두 끝날 때까지 기다린 뒤 오류를 전달하고 후속 함수와 다음 단계를 건너뜁니다. 동기 오류, 비동기 오류, 개발 빌드, 프로덕션 빌드에 같은 정책을 적용합니다. `mapConcurrent`도 실패 후 추가 요청을 시작하지 않고 실행 중인 요청의 완료를 기다립니다.

EventBus는 개별 구독자의 오류를 기록하고 나머지 구독자를 계속 호출합니다. 애플리케이션 조립 모듈은 실패한 명령의 이벤트명과 오류를 기록합니다. 이미 수행한 DOM 작업을 되돌리는 트랜잭션은 제공하지 않습니다.

## 상태와 비동기 요청

시리즈 생성이나 필터 변경처럼 여러 필드가 함께 바뀌는 경우에는 `VaultAdapter.updateState()`로 한 번에 반영합니다. 구독자는 새 키와 이전 목록이 섞인 중간 상태를 보지 않습니다. `resetArticleList()`는 목록과 활성 인덱스를 함께 초기화하고 조회 revision을 증가시킵니다. 어댑터를 파괴할 때도 revision을 증가시킵니다.

`captureArticleSession()`은 조회 시작 시 revision, 세션 키, 페이지 정보, 필터 참조, 검색 조건, 시리즈/셔플 모드, 홈 시리즈 채널 목록을 캡처합니다. 응답을 반영하거나 다음 목록 페이지를 요청하기 전에 캡처가 현재 상태와 같은지 확인합니다. 첫 배치, 스크랩 전체 배치, 홈 시리즈 생성/보충과 백그라운드 인덱스 갱신에 같은 기준을 적용합니다. 무효화된 응답은 목록·인덱스·페이지 이동·실패 토스트에 반영하지 않습니다. 이미 전송한 HTTP 요청 자체를 취소하지는 않으며 기존 타임아웃이 적용됩니다.

목록을 덧붙일 때는 응답이 도착한 시점의 최신 목록과 중복 제거합니다. 홈 시리즈 보충은 읽은 구간과 현재 인덱스를 유지합니다. 새 홈 시리즈는 결과가 있을 때만 완성된 상태로 전환합니다.

페이지 이동은 유효한 배열 인덱스에 대해서만 수행합니다. 같은 페이지에서 이동이 시작된 뒤 들어온 추가 이동 이벤트는 처리하지 않습니다. 브라우저 이동이 예외를 던지면 이전 인덱스를 다시 저장하고 재시도를 허용합니다.

## 저장소 경계

JSON 파싱 성공은 데이터 형식이 올바르다는 뜻이 아닙니다. `config-schema.ts`는 저장 데이터를 `unknown`으로 받아 필터와 UI 설정의 필드별 타입을 확인하고 기본값을 채웁니다. 목록은 같은 origin의 게시글 pathname으로 정규화하며 중복을 제거합니다. 저장 인덱스는 안전한 정수인지 확인하고, 최근 세션 캐시는 문자열 배열인지 확인합니다. 이전 버전의 설정에 새 필드가 없어도 기본값으로 시작합니다.

설정·목록의 JSON은 `ConfigService`가 필드별 memoized getter로 제공하고, `Store`는 getter를 실행하지 않고 상태 스냅샷에 보존합니다. 첫 접근 때 해당 키만 파싱·정규화하며 setter로 교체하면 기존 데이터는 읽지 않습니다. `StorageRepository.getJSON()`은 키별 원본 문자열과 파싱 결과를 캐시하고, 원본 변경·쓰기·삭제 시 갱신합니다. 캐시된 배열과 객체는 직접 수정하지 않습니다. 읽기 기록은 방문 기록과 이어보기를 각각 첫 접근 때 로드하며, 사용하지 않은 이어보기는 `reload()`에서도 파싱하지 않습니다. 이전 저장 형식의 읽기·정리는 첫 이어보기 조회나 존재 확인 시 한 번 실행합니다. 새 형식의 조회에는 이전 코드를 실행하지 않습니다.

채널 필터는 `arcaFeed:channelFilter:{channelId}`에 개별 저장하며 `arcaFeed:filterChannels`는 채널 ID 목록만 보관합니다. `ConfigStorage.filters()`는 채널별 지연 getter를 제공하고, 단일 채널 조회는 해당 필터만 파싱합니다. 필터 목록 열거·스냅샷 복사는 ID 목록과 getter만 복사하며, 필터를 실제로 수정한 채널만 저장합니다. 필터 삭제 시 인덱스와 해당 키를 함께 정리합니다.

설정은 화면 표시·너비(`arcaFeed:displaySettings`), 구독 채널(`arcaFeed:subscriptionSettings`), 본 글 건너뛰기(`arcaFeed:readingSettings`), 마지막 모달 탭(`arcaFeed:lastModalTab`)으로 나눕니다. 상태의 `uiSettings` 인터페이스는 유지하고 각 필드는 소속 저장 그룹을 첫 접근 때만 읽습니다. 필터·설정 변경은 `mergeState()`로 getter를 보존하여 다른 그룹을 읽지 않습니다. 저장 비교도 getter 참조를 비교하고 바뀐 그룹만 직렬화합니다. `arcaFeed:settingsVersion`은 새 설정 형식의 준비 여부를 표시합니다. 방문 기록이 비활성화되어 있으면 `recent_disabled`만 확인하고 `recent_articles` 원본은 읽지 않습니다.

설정 모달은 선택한 탭을 처음 열 때만 생성하며 이후 선택에는 같은 폼을 재사용합니다. 선택하지 않은 기록·이어보기 탭은 조회·렌더링·구독을 시작하지 않습니다. 모달을 닫거나 다시 열 때에는 실제로 생성한 탭의 cleanup만 호출합니다.

상태 배열과 설정 객체는 새 참조로 갱신해야 합니다. 저장은 이전 스냅샷과 참조를 비교하며, 자동 저장은 300ms 동안 변경을 모읍니다. 페이지 이동 전에는 즉시 저장합니다.

`ReadingHistory`는 사이트 방문 기록(`entries`), 이어보기 탐색 정보(`sessions`), 스크롤 위치(`progress`)를 독립적으로 알립니다. 전체 상태의 `readingRevision`과 본 글 표시·건너뛰기는 방문 기록 변경에만 반응합니다. 기록 모달은 필요한 변경만 구독하며, 이어보기 버튼은 클릭 시 최신 위치를 조회합니다.

`entries`는 방문 시각 기준 최신 300개만 제공합니다. 본 글 판정은 사이트의 전체 유효 기록을 사용하며, 표시 제한 때문에 사이트 원본 기록을 수정하지 않습니다.

이어보기 요약과 목록 개수는 `arcaFeed:readingHistory`의 `version: 2` 형식으로 저장하고, 글 목록은 `arcaFeed:readingList:{encodeURIComponent(session.id)}`에 세션별로 저장합니다. 스크롤 위치와 갱신 시각은 `arcaFeed:readingProgress`에 저장합니다. 존재 확인과 모달 렌더링은 요약만 읽으며 목록 getter는 선택한 세션의 목록만 파싱합니다. 다른 세션을 저장·삭제할 때도 보관 한도를 맞추기 위한 실제 축소가 필요하지 않으면 해당 목록을 읽지 않습니다. `reload()`는 종류를 지정할 수 있으며 방문 기록 변경은 방문 기록만, 위치 변경은 위치만 읽습니다. 목록 저장 이벤트는 지연 getter를 갱신하며 목록을 바로 파싱하지 않습니다. 작은 위치 데이터 저장은 큰 목록을 다시 쓰지 않습니다. 최대 20개 세션에 전체 5,000개 링크를 배분하며 각 세션은 최대 2,000개 링크를 보관합니다. 오래된 세션도 현재 글은 유지하지만, 오래된 목록의 일부는 정리될 수 있습니다. 기존 데이터는 위치를 유지하여 자동 이전하고, 변경·삭제는 저장소의 최신 값을 병합해 다른 탭의 위치를 보존합니다. 브라우저 탭 간 동시에 수행되는 읽기·쓰기 전체가 원자적 트랜잭션으로 묶이는 것은 아닙니다.

## 한시적 이어보기 데이터 이전

기존의 통합 이어보기 JSON을 읽는 코드는 [reading-history-migration.ts](../src/vault/reading-history-migration.ts)에 격리했습니다. 지원 종료 후 해당 파일과 `ReadingHistory`의 import, `legacyContexts` 상태, `migrateLegacyContexts()`와 호출 지점, `load()`의 구형 형식 분기를 제거합니다. 구형 분기는 제거 시 알 수 없는 버전을 빈 데이터로 처리하는 버전 검사로 교체합니다. `tests/reading.test.mjs`의 기존 중복 방문 기록 이전·대용량 구형 목록 이전 테스트도 함께 제거하거나 새 형식 검증으로 교체합니다. 새 형식의 요약 조회·선택한 목록 조회·부분 reload 테스트는 유지합니다. 이 절차는 한시적인 호환 코드 제거 작업이며 일반 조회 기능의 일부가 아닙니다.

## 한시적 설정 데이터 이전

통합 채널 필터와 UI 설정을 이전하는 코드는 [config-storage-migration.ts](../src/vault/config-storage-migration.ts)에 격리했습니다. 첫 필터·설정 접근 때 기존 데이터가 있으면 검증한 뒤 새 키로 분리합니다. 기존에 쓰인 새 키는 덮어쓰지 않으며 필터 인덱스와 설정 버전은 그룹 저장이 끝난 뒤 기록합니다. 이후 조회는 기존 통합 JSON을 읽지 않습니다. 지원 종료 후 해당 파일과 `ConfigStorage`의 migration import, 두 `ensureMigrated` 호환 훅 및 호출 지점을 제거합니다. `tests/config-storage.test.mjs`의 한시적 이전 테스트도 함께 제거하고, `tests/architecture.test.mjs`의 통합 설정 fixtures는 새 키 형식으로 바꿉니다. 개별 키 조회·다른 그룹 미조회·부분 저장 테스트는 유지합니다. 이전 지원 종료 시점은 별도로 결정하며 이 호환 로직을 영구 유지하지 않습니다.

```bash
npm test

```

아키텍처 테스트는 실제 TypeScript 모듈을 실행하고 DOM·네트워크·저장소 경계에 어댑터를 제공합니다. 이벤트 순서와 중복 실행, 병렬 실패 후 잔여 작업, 무효화된 응답, 시리즈 상태의 일괄 반영, 이동 경계, 잘못된 저장 데이터, 런타임 순환 참조를 검증합니다. 실제 사이트의 HTML 변경과 브라우저 터치 동작은 별도의 브라우저 검증이 필요합니다.

## 탐색 기능 구분

`vault/navigation-context.ts`의 `navigationMode()`는 채널(`channel`), 일반 시리즈(`series`),
스크랩(`scrap`), 구독 피드(`subscription`)를 구분합니다. 스킵 허용 여부, 읽기 설정 키와
표시 이름, 설정 탭 및 시리즈 열기 버튼은 이 공통 판별을 사용합니다.
구독 피드에서는 최근 본 글 스킵을 사용할 수 있고 일반 시리즈와 스크랩에서는 제한합니다.
기존 저장된 세션과 이어보기 호환을 위해 `isSeriesMode`, `isScrapMode`, `seriesChannels`는
유지하며, 공통 판별 함수가 이 저장 형식을 기능별 모드로 해석합니다.
